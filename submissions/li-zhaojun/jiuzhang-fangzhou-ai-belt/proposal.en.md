## 1. Design Basis & Source Inventory

This proposal uses the official Centennial Jingzhang AI Innovation Belt Urban Design International Call for Qualifications as primary authority, with the three-layer scope, three key areas, design tasks, and outcome depth requirements drawn from clauses 1.3, 1.4, and 1.5. The agent taskbook supplements the three positioning themes, five functions, three-tings plus two-wings structure, six agent tasks, ten co-creation principles, unified review dimensions, and boundary clauses.

Spatial data: official precise redlines and three key-area polygons are not yet available. The proposal uses registered provisional rough substitute boundaries. All derived layers, metrics, and figures are tagged provisional_constraint. After official polygon publication, site boundary, key areas, land use, buildings, roads, green/public space, phasing, and all metrics must be recomputed.

Professional standards include MOHURD-URBAN-DESIGN-MEASURES, MOHURD-CONTROL-DETAILED-PLANNING, MNR-LAND-USE-CLASSIFICATION-GUIDE, MOHURD-ARCH-DESIGN-DEPTH-2016, PROJECT-OFFICIAL-ANNOUNCEMENT, PROJECT-AGENT-OPEN-CALL-TASKBOOK, and the newly added WCAG-2.2-AA (W3C Web Content Accessibility Guidelines 2.2 AA, for accessibility of public spaces and AI service interfaces).

## 2. Three-Layer Scope Framework

- Coordination Research Scope approximately 43.6 km squared: research level; covers the AI innovation ecosystem, industrial chain coordination, and future urban morphology.
- Overall Design Scope approximately 11.41 km squared (site_area_sqm = 11,412,825.386 sqm, EPSG:4548): the main work boundary. All spatial layers are derived within this boundary.
- Key Areas Scope approximately 368.4 ha (key_area_count = 3): three detailed-design key areas:
  - Zhongzhiyuan AI Innovation Acceleration Area approximately 192.1 ha (zhongzhiyuan_area_sqm = 1,929,201.877 sqm)
  - Beijing AI Origin Community approximately 104.3 ha (beijing_ai_origin_community_area_sqm = 1,043,236.909 sqm)
  - Dazhongsi AI Industry Cluster approximately 72.0 ha (dazhongsi_area_sqm = 720,454.221 sqm)

The three key areas are linked by the central Green Spine and cross secondary roads, forming a South showcase - Central translation - North R&D innovation value chain.

## 6. AI+ Scenario Cards (13 cards, including SC-AI-SEN senior inclusion)

Each scenario card carries 8 unified fields (required input, AI role, non-AI fallback, operator, human reviewer, failure-stop conditions, data retention, pilot evaluation). All model performance, latency, and security targets are labelled design target / to be validated - not verified capabilities.

The 13 cards span: SC-AI-01 smart mobility hub, SC-AI-02 open-source release hall, SC-AI-03 near-campus translation station, SC-AI-04 smart consumption street, SC-AI-05 smart economy centre, SC-AI-06 data-element reception, SC-AI-07 robot delivery, SC-AI-08 data-element service building, SC-AI-09 full-stack pavilion, SC-AI-10 safety governance sandbox, SC-AI-11 compute station, SC-AI-12 biennial venue, SC-AI-SEN senior AI neighbourhood living room (with WCAG-2.2-AA accessibility, full-manual retention, refusal-triggered downgrade).

Three industrial test scenarios (SC-AI-IND-01 industrial embodied intelligence, SC-AI-IND-02 robot delivery low-speed trial, SC-AI-IND-03 LLM red-team and standard workshop) provide real-world validation contexts.

Five personas: open-source developer, startup team, enterprise visitor, neighbouring resident, university faculty and student.

## 9. AI Scenario Card Technical Path Examples

> This section presents 4 representative scenario cards with end-to-end technical paths (model selection / data flow / inference latency / failure modes); the remaining 9 are summarized. Implementation requires professional team selection based on concrete suppliers and open-source ecosystem.

### 9.1 SC-AI-02 Open-Source Release Hall — Complete Path Example

**Service target**: Open-source developers (GitHub / OpenSSF / kernel contributors)
**Core goal**: Developer publishes version → on-site talk recording → auto-generate docs + multilingual subtitles → invite review → data feedback

#### 9.1.1 Model Selection (by task)

| Sub-task | Candidate model family | Recommendation reason | Inference budget |
| --- | --- | --- | --- |
| Talk real-time multilingual subtitles | whisper-large-v3 + Volcano/IFLYTEK streaming ASR | Chinese low-latency + offline deployment | < 1.5s P95 |
| Multilingual translation subtitles | Qwen2.5-72B-Instruct (INT8 quantized) / DeepSeek-V3 | Strong Chinese expression + open-source self-deployment | < 2s P95 |
| Recording → docs auto-generation | Claude/GPT-4 series + RAG over talk recording transcript | Long context + accurate citation | Offline batch |
| Review comment sentiment analysis | BERT-base-chinese fine-tuned | High accuracy + lightweight deployment | < 200ms |
| Developer tech Q&A | RAG over project README / docs + LLM | Retrieval augmentation avoids hallucination | < 3s P95 |

#### 9.1.2 Data Flow

```
talk audio/video (16 kHz / 1080p)
    │
    ├→ ASR → transcript (zh) ─→ NMT → multilingual subtitles (en/ja)
    │
    └→ LLM + RAG → structured docs (zh/en/ja) → version release notes
```

#### 9.1.3 Failure Modes & Manual Downgrade

| Failure mode | Detection | Manual downgrade |
| --- | --- | --- |
| ASR accuracy < 85% | WER monitor | Fallback to manual transcript within 5 min |
| LLM hallucination | Citation coverage rate < 95% | Manual review queue + human rewrite |
| NMT terminology mistranslation | Terminology lookup rate < 90% | Domain expert terminology confirmation |

### 9.2 SC-AI-07 Robot Delivery — Complete Path Example

**Service target**: residents, merchants within 500m of East Wing
**Core goal**: User places order → robot receives dispatch → route planning → barrier avoidance → delivery completion confirmation

#### 9.2.1 Model Selection

| Sub-task | Model family | Reason | Latency |
| --- | --- | --- | --- |
| Visual SLAM | ORB-SLAM3 / RTAB-Map | Open-source + low-power | 30 fps real-time |
| Pedestrian / vehicle detection | YOLOv8-nano | Lightweight edge deployment | < 50ms |
| Path planning | Hybrid A* + DWA | Dynamic obstacle avoidance | < 100ms |
| Natural language interaction | Whisper + Qwen2.5-1.5B | Edge-side inference | < 1s |

#### 9.2.2 Failure Modes & Emergency Stop

- Lidar sensor failure → immediate stop + manual remote takeover
- Pedestrian proximity < 1.5m → slow stop + voice warning
- Path blocked > 60s → manual takeover + return to dock

### 9.3 SC-AI-10 Safety Governance Sandbox — Complete Path Example

**Service target**: research institutions, governance committee
**Core goal**: AI system red-team test → risk classification → sandbox isolation → governance committee review → release decision

#### 9.3.1 Sandbox Architecture

Three-layer isolation: network layer (VLAN isolation) + compute layer (K8s namespace) + data layer (encrypted storage + access audit)

#### 9.3.2 Data Source

(a) Public toxicity datasets (ToxicChat / BeaverTails etc.); (b) Governance committee custom attack vector library

### 9.4 SC-AI-SEN Senior AI Neighbourhood Living Room — Complete Path Example (v4.3, key)

**Service target**: neighbourhood seniors 60+ (with explicit consent + family authorization)
**Core design commitment** (350 words): Neighbourhood housekeeper + AI backend only + full manual retention + semi-annual audit + refusal rate trigger downgrade + WCAG-2.2-AA

| Field | Design | Source |
| --- | --- | --- |
| Required input | Senior self-declared needs (voice / text / manual) | consent form |
| AI role | Backend suggestion only (no autonomous action) | - |
| Non-AI fallback | Full manual housekeeper always available | required |
