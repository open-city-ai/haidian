# 京张开放题：方案叙事摘要

**城市出题，全球共答，公众验收。**

“京张开放题｜JING-ZHANG OPEN CHALLENGES”把百年京张组织成一套公共问题治理与城市设计框架。机制拟要求每道问题先公开题主、受益人、数据与权利条件、风险、测试地点、成功与停止条件、人工负责人和到期日，再进入跨机构共答、专业验证、受控场测和公众验收；失败、主动停止、申诉与到期退役项目应与通过项目同版记录。

空间功能建议分工如下：AI 原点社区用于提题、开放研究与跨机构组队；众智园用于模型、具身 AI 与能源算法的受控验证；小月河场景测试翼布置低速、低风险、可撤回的反馈界面；南段的大钟寺任务功能原型用于讨论公众比较、产品说明和中小企业采用；中关村科技服务翼用于匹配知识产权、人才、算力、数据与专业服务。横向日常照护网连接社区、园区、校园和公共空间。

这里的“南段功能原型”不是站点落位。社区复核 #1029 表明 `PROV-KEY-003` 距大钟寺站约 2.26 km，本轮不据此讨论站口、四象限或客流工程；社区复核 #846 也表明临时 SITE 与 OSM 已测绘遗址公园不相交、最近约 412.5 m。两项复核只用于披露当前底板限制，不用于移动临时坐标或定义正式边界。

遮阴、座椅、过街、无障碍、导视、报修、一线劳动和小微经营等日常修补与照护，与大型研发和活动具有同等优先级。机制要求每条公众意见生成回执，记录采纳状态、理由、责任人、复核节点和申诉渠道；无法控制风险、维护负担或公共影响的试验应降级、暂停或退出。

VI 以 3 段开放框、2 个外向接口和 1 个中央公众圆点表达三区、两翼和公众判断，并用“? 提题、{ } 共答、△ 测试、○ 评议、↺ 迭代或退出”显示状态。三个功能地标分别是百年难题档案馆、全球解题台和城市评议厅；它们记录题主、解题者、验证者、公众评议者和复盘者，不以企业 Logo 墙代替公共贡献。

12 张场景卡逐一映射 `geometry/public_space.geojson` 的 SCN-001 至 SCN-012，其中 T01—T03 为产业测试验证场景。全部场景共用 G0 纸面审查、G1 合成数据实验、G2 封闭场测、G3 有监督公共 Beta、G4 有条件复制或退役的成熟度闸门。`visual/assets/question-ledger.example.json` 把每道题的责任角色、验证条件、停止条件、回执状态和到期规则写成机器可读示例；当前 12 项均停留在 G0 概念候选状态。

本摘要由 proposal.md 派生，不能替代主体方案、GeoJSON、metrics、三类矩阵、图纸或自检。当前边界和三处重点区均为 provisional constraint；面积、比例和场景落位只用于概念设计与讨论。官方 polygon、控规、权属、现状、交通、市政、消防、文保和工程资料到位后，应由专业团队整体更新。本方案不构成政府承诺、规划审批、拆改留结论、工程可行性、投资或活动安排。
