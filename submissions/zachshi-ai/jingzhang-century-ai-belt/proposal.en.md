## 1. Overall Concept · agent.1 · Master Framework

### 1.1 Core Proposition

Rewrite the Jing-Zhang Railway (Zhan Tianyou, 1909) as a **globally readable AI urban open-source protocol**.

**The analogy**: Linux kernel commit logs ≠ code itself; similarly, the Jing-Zhang "open protocol" ≠ physical tracks, but a **verifiable, contributable, exitable urban intelligence collaboration framework**.

| Heritage Element | Open-Source Analogy | Meaning |
|---|---|---|
| Switchback (之字形) | Fault tolerance | Local failure does not affect overall operation |
| Station log (站员签认) | Audit trail | Every step traceable and auditable |
| Segmented dispatch (分段发车) | Modular autonomy | Independent decision at each station, protocol-connected |
| Open platform (开放站台) | Open contribution | Any entity may apply to contribute |

## 2. AI Full-Stack Ecosystem · agent.2 · Technical Architecture

### 2.1 Model Annulus Station (ZZY-005) — AI Full-Stack Autonomous Verification

**Goal**: Establish AI full-stack verification system within PROV-KEY-001, ensuring model safety and auditability.

**Three-layer architecture**:

1. **Foundation model layer**: Open-source models (Llama / Qwen) + edge deployment
2. **Verification middleware**: Automated testing covering functional correctness, safety boundaries, privacy compliance
3. **Public interface layer**: RESTful API; all agent interactions must pass through this audit layer

**Safety mechanisms**:
- Physical isolation: Verification network completely physically isolated from production network
- Human audit: Quarterly red team exercise by human experts
- Exit trigger: Any single-point failure can trigger full-station pause

### 2.2 Protocol Distribution Station (BUPT-004) — Data Distribution & Communication

**Goal**: Ensure public data (environmental quality, traffic flow, event notifications) distributed through trusted channels.

**Distribution protocol specification**:
- Data format: JSON + schema declaration
- Update frequency: Real-time (< 5s latency)
- Access control: No registration required, direct public endpoint access

### 2.3 Embodied Mobility Station (BHG-003) — Robot Coexistence Testing

**Goal**: Test low-speed robot and pedestrian coexistence safety in controlled environment.

**Rules**:
- Maximum robot speed: 1.5 m/s (within public space)
- Hardware emergency stop: Automatic trigger when pedestrian approaches within 2m
- Operator: On-site staff with robot operation certification

## 4. Open Collaboration & Governance Framework

### 4.1 Five Data Governance Principles

| Principle | Implementation |
|---|---|
| Minimum data | Each scenario collects only data strictly necessary for function |
| Human review | Key decisions (heritage narration, medical paths) require human countersign |
| Pausable | Any scenario can be paused at any time without affecting other scenarios |
| Exitable | Contributors can apply to delete their contribution records |
| Public model cards | Every AI model discloses training data sources, performance metrics, known limitations |

### 4.2 Protocol Amendment Process

1. **Proposal**: Any entity may submit an amendment proposal to DZS-006 station
2. **Deliberation**: 30-day public deliberation period (online + offline)
3. **Vote**: DZS-006 Station Affairs Committee (resident representatives, open-source community, technical experts) votes
4. **Execute**: Upon approval, written into protocol version number, synchronized across the network
