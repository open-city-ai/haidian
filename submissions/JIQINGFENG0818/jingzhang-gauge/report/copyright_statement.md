# Copyright and Attribution Statement

Every claim below is verifiable directly from the committed files of this package. Nothing is asserted
as "cleared" without a check a reviewer can repeat.

## Base spatial data

This package contains **no third-party spatial dataset**. Every geometry feature declares its own
provenance in its properties, and the layers fall into exactly two classes:

- `source_type: agent_generated_design` / `geometry_role: design_proposal` — originally designed for
  this submission: `roads.geojson` (246 features), `land_use.geojson` (167), `buildings.geojson` (552),
  `green_space.geojson` (85), `public_space.geojson` (9), `phasing.geojson` (3).
- `source_type: agent_inferred_from_public_data` / `geometry_role: provisional_constraint` — derived
  from the organizer-supplied `provisional_boundaries.geojson`: `site_boundary.geojson` (1),
  `key_areas.geojson` (3), `constraints.geojson` (4).

No OpenStreetMap extract, commercial map tile, satellite image, aerial photograph or licensed survey
dataset is used by, or required for, this package. `sources.json` accordingly registers no external
spatial data source. (The author's other submission, `submissions/JIQINGFENG0818/jingzhang-patrol/`,
does use an OSM extract under ODbL 1.0 and carries its own attribution; the geometry in *this* package
does not depend on it.)

## Boundaries

`geometry/site_boundary.geojson` and `geometry/key_areas.geojson` reproduce the organizer-supplied
provisional substitute boundaries. They are **not official redlines** and are not a precise-area basis;
once official boundary and key-area data are published, the affected geometry, metrics and drawings must
be recalculated.

One known defect in that organizer geometry is carried over and **disclosed rather than silently
corrected**: `PROV-KEY-003` (Dazhongsi AI industry cluster) has its centroid near Beijing North Station
rather than Dazhongsi. The offset was raised in issue #1029, confirmed by the maintainers, and clarified
in #1036 (placeholder rectangles are ordered by announced area only and are not yet anchored to stations
or roads; the maintainers state they will not translate the coordinates). It is recorded as assumption
`A-KEY003-OFFSET-001` with `status: pending_official_data`, and `ISSUE-1029` is registered in
`sources.json`.

## Generated content

All narrative text, design geometry, figures, drawings and HTML in this package were generated by the
declared AI agent (see `agent.json` and the synchronized `manifest.agent` block) for this submission.
No third-party photograph, illustration, icon set, map graphic, chart template, page template or
stylesheet is embedded or referenced.

## Rich media under `assets/media/`

The five files under `assets/media/` (a cover image, one silent video, its poster, caption track and
transcript) were generated by the same declared AI agent, frame by frame with matplotlib and encoded
with ffmpeg/libx264. Every map shape in them is drawn **only** from this package's committed
`geometry/*.geojson`, and every number shown is taken **only** from this package's `metrics.json` and
existing narrative — a reviewer can re-derive each frame's content from those files. The video is
silent: it contains no speech, music or sound effects, so no audio rights exist to clear; this is
stated in `assets/media/gauge-mechanism.md`, which also records the generation method. No third-party
footage, photograph, satellite or aerial image, map tile, stock asset, icon set or template of any
kind is embedded, and no real person is depicted. The media are conceptual mechanism explainers and
are marked on every frame as conceptual content on provisional boundaries — they are not official
renderings, approved plans, built results or verified site conditions.

## Interactive 3D tour under `visual/assets/`

Section 14 of `visual/index.html` / `index.en.html` embeds an interactive 3D tour driven by two local
scripts written for this submission by the same declared AI agent: `visual/assets/gauge-tour-data.js`
(a pre-computed geometry payload) and `visual/assets/gauge-tour.js` (a hand-written WebGL 1 renderer).
**No third-party runtime library is embedded or referenced** — no Three.js, no framework, no loader —
and the code contains **no network API of any kind**: a reviewer can grep both files for `fetch(`,
`XMLHttpRequest`, `WebSocket`, `EventSource` or `sendBeacon` and find none; the page keeps working
offline. The payload is derived **only** from this package's committed `geometry/*.geojson`
(EPSG:4326 to EPSG:4548 with pyproj, topology-preserving simplification with shapely, constrained
Delaunay triangulation with Shewchuk's Triangle), so every shape on screen can be re-derived from the
committed geometry. Building volumes are conceptual massing at `floors_assumed x 3.2 m` (assumed
storeys, not an approved FAR basis), shown at true scale by default; the optional x3 vertical
exaggeration is labelled on screen while active. The scene sits on the organizer's provisional
substitute boundaries and is marked as such in the section text; it is not an official rendering,
an approved plan or a verified site condition. The tour honors the system reduced-motion preference
and degrades to a text notice pointing at the static figures when JavaScript or WebGL is unavailable.

## Typefaces

Figures and drawings are rendered with matplotlib using **Noto Sans CJK**, licensed under the
SIL Open Font License 1.1 (OFL). The four PDFs in `drawings/` contain zero `FontFile`, `FontFile2` or
`FontFile3` objects: all glyphs are rasterised into the PNG and PDF output, so those files carry no
font program. A reviewer can confirm this by scanning the PDFs for those object names.

The four HTML deliverables — `report/proposal.html`, `report/proposal.en.html`, `visual/index.html`
and `visual/index.en.html` — each embed **one** font program: a WOFF2 subset of **Noto Sans CJK SC
Regular** (© 2014-2021 Adobe, OFL 1.1, "Noto" is a trademark of Google Inc.), written inline in the
page's own `<style>` block as a base64 `data:` URI inside a single `@font-face` rule. Each subset is
limited to the non-ASCII characters that the page it lives in actually uses (the exact character count
is stated in the CSS comment next to the rule), which keeps the payload at roughly 150 KB for the
Chinese pages and 14 KB for the English pages. The subset is a *Modified Version* in OFL terms and is
therefore renamed **`JZ Gauge CJK`** (OFL §3: no Reserved Font Name or trademark is reused); the
original copyright (name ID 0), trademark (7) and licence (13, 14) records are retained inside the
font, and the complete OFL text is reproduced in Appendix A below (OFL §2). **No standalone font file
is added to the package** — the font travels only inside those four HTML files.

The reason for embedding is rendering, not styling: headless review hosts frequently have no CJK
system font, and a page that only declares a system font stack renders every Chinese glyph there as
a box. With the subset in place the Chinese text of all four pages renders identically on a host with
no CJK font at all (verified by screenshotting each page with headless Chromium under a fontconfig
that exposes only DejaVu Sans). The system stack after `JZ Gauge CJK` is unchanged, so hosts that do
have PingFang / Microsoft YaHei / Noto Sans CJK installed keep using them for everything else.

## Offline guarantee

`visual/index.html`, `visual/index.en.html`, `report/proposal.html` and `report/proposal.en.html`
contain **no absolute URL of any kind**, and no `<iframe>`, `<form>`, `<link>`, `@import`,
`url(http…)`, CDN reference, remote map tile, external font, `fetch`, `XMLHttpRequest`, `WebSocket` or
`EventSource`. The only `@font-face` rule in each file points at an inline `data:` URI (the embedded
subset described above), never at a remote or external resource.

Each `visual/index*.html` renders from one inline `<svg>`, one inline `<script>` (1,053 bytes, no
`src` attribute) that only manipulates the page's own DOM, and the two local tour scripts referenced by
relative path (`assets/gauge-tour-data.js`, `assets/gauge-tour.js`; see the 3D tour section above). The
two `report/*.html` files reference the ten figures by relative path (`../assets/figures/*.png`); all
ten files are inside this package and are declared with SHA-256 in `manifest.json`. Every file opens
correctly with no network connection.

No rendered asset in this package contains an absolute URL. The only absolute URLs anywhere in the
package are in JSON metadata (the Beijing municipal announcement cited in `sources.json`, and the
GitHub issue cited above) and in the licence text reproduced in Appendix A of this statement.
