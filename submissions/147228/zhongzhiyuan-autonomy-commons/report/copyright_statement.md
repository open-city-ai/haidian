## Scope of this statement

## Third-party materials and external dependencies

- No third-party photographs, illustrations, logos, map tiles, remote JavaScript, remote CSS, remote fonts, iframe, tracker or external API is embedded in the offline HTML pages.
- No registered logo or trademark is reproduced. The “two rails / three nodes / two switches” mark is a self-generated concept direction and must receive a separate trademark, accessibility and brand review before use.
- Local system fonts may be used by the renderer for CJK text; no font file or font licence is redistributed in this package.
- Public data and repository/user-provided materials are used only within the scope and attribution recorded in `sources.json`, `data/source_registry.json`, and the evidence ledger. A public URL is not treated as a blanket licence for images or derivative assets.
- The package does not include historical photographs or corporate promotional imagery. Historical interpretation is expressed with text, self-generated geometry and diagrams unless a future contributor registers a rights-cleared asset.

## Clearance protocol for future contributors

Before adding any image, map, logo, font, data extract, event content or code dependency, a contributor must record: the exact path, author or provider, source URL or permission record, licence, attribution text, allowed derivative use, retrieval date, intended display, and SHA-256 hash. The contributor must then update `sources.json`, `visual/assets/copyright-ledger.json`, `manifest.json`, and the relevant narrative or figure caption. Unclear material stays out of the public package.

The ledger's `clearance_status` distinguishes self-generated material from official public data with attribution. `third_party_materials` is intentionally empty for the v1.7 package. This is submission evidence, not a legal opinion; rights-holder confirmation remains necessary if the future implementation team introduces new content.

## Privacy, safety, and public-interest boundary

The proposal does not require facial recognition or individual trajectory retention. Scenario data are minimum-necessary and aggregated where possible; health navigation is non-diagnostic; data demonstrations remain in a sandbox; and every active component has a passive human equivalent and a withdrawal path. A failure of rights, safety, drainage, accessibility or resident-impact gates triggers human operation, a pause or removal. Residents must be able to use the space, receive service and complain without an app, account or biometric identifier.

## Verification

Reviewers can audit this statement by checking every manifest path against `visual/assets/copyright-ledger.json`, opening the local HTML pages with network access disabled, and rerunning the repository self-check and manifest hash refresh. Any mismatch, unregistered asset or remote runtime dependency is a release blocker.
