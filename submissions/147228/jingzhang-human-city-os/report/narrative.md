# 一页摘要｜京张人本城市操作系统 v1.0

## v1.0 实质性升级

本轮把“待确认责任”变成五阶段授权前启动程序：范围冻结与启动登记、资格/利益冲突复核、公众告知与异议、人类责任与授权记录、版本交接/复核/退出。程序覆盖 6/6 准备度场景、3/3 发布门和 8/8 必填字段，但明确保持 `authorized=false`、`operator_confirmed=false`，不声称机构、运营者、许可、现场运行或绩效已经确定。[data:visual/assets/governance-startup-protocol.json]

同时登记五个“AI 辅助整理/回放 → 人类判断 → 保留或拒绝”的设计取舍，分别回接发布门、普通人服务链、空间参数取舍、合成人本交接凭证和启动程序。该日志是事后结构化索引，不是逐字模型对话、外部联网记录或现场实验；证据不足仍保持概念或 `unknown`。[data:visual/assets/ai-design-exploration-log.json]

## 核心命题

本方案不把“更多 AI”当作答案，而把京张创新带设计为一套可审计、可拒绝、可回滚的城市版本：A 组保障人的尊严，B 组增加机器可调用能力，C 组把算电、气候、数据授权与版本治理设为硬门槛，D 组让技术、标准与知识向京津冀、小团队和国际服务外溢。

## v0.9 实质性加固

本轮新增合成人本交接凭证的逐案例回放字段。3 个合成案例各自登记人工替代、最小资料、停止理由、摘要哈希和 release note 字段；在授权前，摘要哈希与 release note 明确保持未生成或未关联。无网络 runner 逐项检查 8/8 字段，并用缺失案例字段的负样本验证契约不会只在顶层声明。

## v0.8 实质性升级

本轮把 6 个测试类场景的“可以开始”条件集中登记到 `visual/assets/pilot-readiness-register.json`：基线、观察对象与时间窗、成功条件、停止条件、人工替代、最终责任、复核周期和删除证明逐项列出。当前状态保持为未采集、待授权主体确定或授权前冻结，没有用示范数字冒充现场结果。台账首页明确记录没有现场走访、居民验证、利益相关方参与或现场测量；离线 runner 复核 6/6 场景、8/8 字段，并以 3 个负样本检验缺字段、误填数值和误填责任值都会被拒绝。

## 空间操作

43.6 平方公里统筹研究范围负责外溢机制，约 11.4 平方公里总体设计范围形成六层功能操作系统，众智园、AI 原点社区和大钟寺承担差异化验证。临时总体边界内设置社区保留与服务、国际/OPC 服务、技能再造与公共数据学习、可逆留白、城市 API 与具身研发、无屏绿地与气候韧性六层；人本网络与机器测试网络在人工接管、低速、保险和事故复盘条件下相交。

## 人与场景

六类核心使用者包括原住民/老人、被替代风险劳动者、AI 从业者、OPC/小团队、公共服务人员和国际访客。17 张场景卡对应 16 个几何节点，人的尊严 A 组 4 项、机器可用 B 组 4 项、硬约束 C 组 5 项、外溢 D 组 4 项；其中 6 项属于受控测试。社区保留账本、带薪技能再造、人工通道、无屏恢复、城市 API、硅基通行权、算电余热审计和公共数据授权都设置停止与回滚条件。

## 三个城市版本

- v0.1：建立清权基线、公众问题清单、人工服务底线和无屏公共空间。
- v0.2：开展可逆小试、独立评价、能耗计量、人工接管和事故演练。
- v1.0：只扩展通过公共利益、能源、气候、无障碍与可回滚审查的项目，并发布年度 release note。

## v0.7 实质性升级

v0.7 不把“评审导航”误写成官方评分：它将仓库 formal scorecard 的 7 项工作流问题及模板百分比分开标注为仓库维护者流程，将任务书的 13 项统一评审维度单列且不推断权重。新增离线导航审计同时读取任务书、仓库脚本与包内路径，验证 13/13 任务书维度、7/7 工作流问题、模板权重对齐及 42/42 包内路径；缺少维度或路径不存在时的负样本必须 FAIL。图 10 把两套问题、五条证据脊与“资料不足则保持概念 / unknown”的共同边界压缩为一页。它不产生分数、官方评审结论、许可或实施证明。

## v0.6 实质性升级

v0.6 新增图 09“人本城市验收图谱”，将原有 6 类使用者、16 张场景卡、10 条代表性路径、临时空间锚点和 3 段发布门放到同一审阅面。每张人物卡同时显示人本底线、人工替代和停止/回退，避免社区保留、就业转型、夜间健康、OPC、公服责任与无障碍仅留在分散台账中。离线检查验证 6/6 人物路径、16/16 场景卡、10/10 代表链接、30/30 代表性空间引用、45/45 场景空间引用和 3/3 发布门；虚构人物锚点必须 FAIL。它只证明包内引用可追溯，不证明现实人群覆盖、人员、服务、许可、工程或绩效。

## v0.5 实质性升级

v0.5 新增图 08 与两种非尺度化空间接口原型：AI 原点社区将无障碍步行、人工/电话/纸面入口、技能转型与无屏绿地并置；众智园将人行优先缓冲、人工停止/事故复盘、受限测试和海绵退避并置。每层绑定既有空间锚点、场景、普通人服务链、资料门与停止动作，绝不画成真实道路横断面、工程尺寸或运营承诺。离线检查重解 2 个原型的全部引用并运行虚构锚点负样本，17 项结构检查通过只证明“可回溯”，不证明真实人员、无障碍、安全、许可或绩效。

## v0.4 实质性升级

v0.4 新增“资料就绪度”台账与图 07：七条路径将空间/权属、社区/就业、人工通道、数据授权、人机安全、算电余热与水文校准，分别绑定到 assumption、场景、空间层、指标、发布门、最低证据、建议审阅角色、资料缺失时的回退动作和全量重算触发器。它不指定运营方、审批时点或实施承诺；资料不足时，相关内容仍是概念建议或 `unknown`。本轮也新增持续就业转型率和人工通道等效可用率两项 `unknown` 指标，明确不能用走廊长度、培训人次、网页可访问性或全球暴露率替代真实结果。

## v0.3 实质性升级

本轮在不改动临时边界坐标、面积、比例、线长、场景数量或任何 unknown 指标的前提下，重绘六张中英对照空间图与双语 A3/A0 图册。所有图层继续直接派生自同一组 GeoJSON 和 `metrics.json`，采用 EPSG:4548 内部复算，并为走廊阅读作 90° 顺时针显示旋转；原始北向明确标注为“北 →”。图号、比例尺、可对应图例和精度说明提高了审阅可读性，但不把临时几何升级为官方红线、测绘成果、工程线位或法定控制。完整方法与限制见 `visual/assets/spatial-figure-method.json`。

## v0.2 实质性升级

本轮不改动临时边界坐标、面积、比例、线长或任何 unknown 指标，也不触碰公共图库的排序文件。新增的是一套可审阅的“发布门—场景卡—退出证据”链：16 个场景各自记录空间锚点、建议对象、人工替代、资料边界、验收所需证据与停止条件；三段发布门把“何时可以研究、何时必须暂停、何时才可由专业主体重新审查”写成明确规则。它不表示试点已经获批、部署或可行。

## 可核验证据

所有 `known` 空间指标均由同一组 GeoJSON 投影至 EPSG:4548 后复算。临时边界面积为 11,412,825.386 平方米；设计绿地约 1,269,256.687 平方米（11.12%）；公共空间约 121,447.158 平方米（1.06%）；社区保留支撑分区约 18.28%；可逆留白约 15.09%。这些是概念设计层数值，不是官方红线、法定指标或社会绩效。

居民真实保留率、持续就业转型率、人工通道等效可用率、运行 PUE、绿电占比和余热回收量均保持 `unknown`，分别等待家庭基线、带薪路径与随访、服务走读、实际能耗、绿电凭证和热网计量。北京现行智算中心 PUE 要求与绿电政策语境只作为设计门槛和基线，不被写成项目既有成绩。
