# JINGZHANG ON TIME — The Urban Operating Diagram for AI Public Services

> **Proposition: AI public services in the city should run like trains on a published timetable — punctuality is verifiable, changes require public notice, suspensions are announced in advance, delays come with compensation, and cross-service transfers are connected by schedule.**
>
> Version: v6.0 | 2026-08-16 | YuanYii | sixth submission (execution-evidence on disk + assertion-calibre unification + governance-protocol chapter restored + mechanism narrative deepened)

## Operating Diagram Governance Protocol and Open Operation

[metric:punctuality_rate] [data:visual/assets/governance/timetable.schema.json]

**Urban Operating Diagram (v1.0).** Every AI public service registers its spatio-temporal schedule (service ID / interval / window / punctuality definition / delay thresholds / change notice / suspension notice / transfer / AI-off path / stop condition — ten fields). Publicly queryable (timetable halls + stop information points), machine-readable (timetable.schema.json), machine-verifiable (check_timetable.js).

**Three-signal display.** Green = punctual; amber = delayed with human takeover; red = suspended, reverting to the no-AI baseline. Signal posts make governance state spatially legible — residents read the state of the belt's AI services without opening any app.

**Punctuality KPIs.** Punctual = completed on schedule without human takeover. Six KPIs (punctuality / delay / suspension fulfilment / window execution / transfer connection / compensation fulfilment) are sourced from the diagram log, published monthly (T-02), archived annually (T-08). Pre-pilot all unknown — design blueprints are never presented as measured performance.

**Weekly window.** Every Tuesday 06:00–12:00: AI off line-wide for maintenance (equipment / model / data / interface), public space returns to no-AI state — periodic AI exit becomes civic rhythm, not emergency. Execution enters KPI-4; three consecutive missed windows trigger a hard stop.

**Transfer protocol.** Cross-district handovers follow transfer times; receipts require human sign-off; delays never silently skip a transfer; no receipt, no next service.

**Gates G0–G4.** Registration → baseline verification → controlled trial → punctuality assessment → release/suspend. Each gate has inputs, judgement and stop actions; years and hype never substitute for evidence gates. Suspension is a qualified outcome (falsify-first).

**Paired testing (AI on / AI off).** Same task, both states; equivalence gap (completion / time / accessibility / appeal) is mandatory evidence for registration; denominators include failures — a sample of successes only is not evidence.

**Operating community (five parties).** District authority (lead + authorization), park operator (execution), university alliance (resources), community representatives (veto), independent audit (review). No single party decides everything. Five-fund firewall (public base / research commission / public-interest commission / time-limited sponsorship / operating revenue); three ledgers (capex / opex / exit reserve) required before any G3 pilot. Civic Value Protocol: 10–20% of corridor commercial computing-node and scenario-test revenue studied for injection into the community public-value fund (voluntary CSR charter).

**90-day first service, gate by gate** (T-07 minimal implementation unit, Origin 100-metre window):

| Phase | Gate | Inputs | Judgement | Stop action |
|---|---|---|---|---|
| D0–D30 registration & sample section | G0→G1 | facility list, timetable draft, AI-off-path drill records | timetable entries pass check_timetable.js; equivalent-path drill observed passing | registration fails → no slot, facilities withdrawn |
| D31–D60 demonstration-interval trial | G1→G2 | diagram logs (6 event types begin), paired-test data | punctuality judgement executable; delay→compensation linkage reproducible | insufficient data → extend observation, no assessment |
| D61–D90 punctuality assessment | G2→G3 | 30-day full logs, six KPIs, baseline compare (BL-01~04) | KPI vs pre-pilot baseline, basis published in advance; group results reported separately | below bar → G3 suspension — a qualified outcome: three falsifiable judgements completed |

**Delay-compensation chain** (T-05, trigger to fulfilment): diagram log delay event (delay_minutes > threshold) → signal post turns amber + board flags (T-02/T-06) → kiosk auto-opens human alternative / equivalent path / appeal → fulfilment logged (compensation event) → fulfilment rate (KPI-6) published monthly → unfulfilled cases enter the Yearbook failure archive (T-08). Any missing link triggers the stop condition.
