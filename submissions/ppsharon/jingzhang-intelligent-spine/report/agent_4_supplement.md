# Agent.4 补充 — 公共空间组件库

> 对应 `brief/site-package/agent_taskbook.json` agent.4 任务：公共空间组件库。

---

## 1. 设计理念

**模块化 + 可扩展 + AI原生**

公共空间组件不是固定设施，而是可迭代、可替换、可升级的"城市API"——每个组件都有标准接口，允许根据技术发展和社区需求进行热插拔更新。

## 2. 组件分类体系

| 类别 | 组件 | 功能 | 技术接口 | 可升级性 |
|------|------|------|---------|---------|
| **基础设施组件** | 端侧算力桩 | 边缘计算节点 | REST API / gRPC | 算力模块可更换 |
| | 智能灯杆 | 照明+感知+通信 | MQTT / 5G | 传感器可扩展 |
| | 分布式储能舱 | 光伏+储能 | 电网协议 | 容量可扩展 |
| **服务组件** | AI服务亭 | 语音交互+信息查询 | NLP API | 模型可更新 |
| | 无人配送站 | 快递/外卖接收 | 物流API | 容量可扩展 |
| | 智能座椅 | 充电+环境监测 | IoT协议 | 功能模块可更换 |
| **交互组件** | 代码贡献墙 | 开源项目可视化 | GitHub API | 数据实时同步 |
| | AI测试角 | 场景体验+反馈收集 | 测试框架API | 场景可替换 |
| | 数字留言板 | 社区建言+投票 | 区块链存证 | 规则可配置 |
| **生态组件** | 雨水花园模块 | 海绵城市+监测 | 传感器网络 | 植物可替换 |
| | 垂直绿化舱 | 立体绿化+碳监测 | 环境监测API | 植物+传感器可换 |
| | 昆虫旅馆 | 生物多样性 | 视觉识别 | 模型可更新 |

## 3. 标准接口规范

每个组件必须提供：

```
{
  "component_id": "unique-id",
  "type": "infrastructure|service|interaction|ecology",
  "version": "1.0.0",
  "api_endpoint": "https://api.jingzhang.ai/components/{id}",
  "data_schema": "https://schema.jingzhang.ai/v1/{type}.json",
  "update_method": "OTA|hot-swap|scheduled",
  "maintenance_window": "02:00-05:00",
  "dependency": ["power", "network", "compute"],
  "kpi": {
    "availability": "99.5%",
    "response_time": "<200ms",
    "data_freshness": "<1min"
  }
}
```

## 4. 组件布局原则

| 空间类型 | 必配组件 | 选配组件 |
|---------|---------|---------|
| 遗址公园步道 | 智能灯杆、AI服务亭、智能座椅 | 代码贡献墙、雨水花园 |
| 广场节点 | 端侧算力桩、数字留言板、无人配送站 | AI测试角、垂直绿化舱 |
| 滨水空间 | 智能灯杆、生态监测舱 | 昆虫旅馆、雨水花园 |
| 社区口袋公园 | AI服务亭、智能座椅、数字留言板 | 无人配送站、垂直绿化舱 |

## 5. 迭代机制

- **季度评估**：每个组件的使用率、故障率、用户满意度
- **年度升级**：根据技术发展和社区需求，替换20%组件
- **实验区域**：预留10%空间用于测试新型组件（如脑机接口体验角、全息投影发布台等）
