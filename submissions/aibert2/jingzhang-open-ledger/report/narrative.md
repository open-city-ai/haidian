# 国际方法研究：转译而非复制 / International Methods: Translate, Do Not Copy

本附录记录 v1.1 延续并完善的八个国际案例。它们不是海淀的空间、政策、运营或绩效证据；每个案例只贡献一个可检验的设计操作，并同时记录不应照搬的内容。

| 案例 / Case | 可借鉴的操作 / Operation | 海淀转译 / Local translation | 不照搬什么 / Non-copying caution |
| --- | --- | --- | --- |
| High Line, New York | 将线性铁路遗存视作公共骨架与持续管理对象。 | 京张“轨痕”成为连续慢行、树荫、停留与公共说明的骨架；优先采用可逆、可维护的小尺度界面。 | 不复制形象、植物、尺度、旅游经济或地产逻辑；不使用其摄影或图像。 |
| Superkilen, Copenhagen | 让使用者共同参与公共身份和物件叙事。 | 用多语导视、问题卡、共创编辑桌和可替换内容层，让学生、居民和服务人员共同写作。 | 不移植具体物件、图案或“全球拼贴”审美。 |
| Oodi, Helsinki | 将安静工作、预约协作、制作、学习和无障碍服务放在同一公共机构中。 | AI原点设置可预约协作桌、安静角、人工服务点和可解释学习界面。 | 不照抄建筑形象或假定同等服务能力、经费与运营规则。 |
| one-north, Singapore | 以弹性空间联结研发、创业、支持机构和日常设施。 | 科技服务翼以“可进入的服务前台”联结人才、转化、IP、资金、算力和场景问题。 | 不将其产业清单、土地组织或体量套用到海淀。 |
| STATION F, Paris | 用阶段化项目和伙伴接口组织创新生态，而不只依靠空间形象。 | 将‘源—测—发—审—返’作为项目/服务的进场、试用、复核和回报接口。 | 不转移其机构、伙伴、入驻数据、融资数字或校园规模。 |
| Smart Kalasatama, Helsinki | 用居民、企业和城市之间的共同开发把日常城市问题转成可讨论试验。 | 三类验证场以代表性使用者、低数据样机、公开反馈和复盘为进入条件。 | 不复制其数据实践、治理模型、伙伴或绩效指标。 |
| Ars Electronica, Linz | 把技术、文化、学习和国际公共叙事组织成持续发生的城市接口。 | ‘京张开放账本周’用中英双语场景协议、公开复盘和城市走读连接本地试验与国际同行。 | 不使用其活动品牌、艺术作品、合作关系、规模或观众数据。 |
| Cheonggyecheon, Seoul | 将绿色/水系廊道与安全、维护、文化使用规则共同组织。 | 小月河场景翼将树荫、雨水、无障碍停留、季节提示和维护责任作为场景底板。 | 不主张相同水文、生态或工程性能；不把其工程路径作为当地方案。 |

## 中国—北京—海淀校准 / China–Beijing–Haidian calibration

- **中国公共服务语境：** 所有AI场景坚持最小数据、明确用途、人工替代、退出和复核；不以“聪明”取代人的尊严和可及性。
- **北京场景语境：** 将“技术突破—场景验证—产业应用”的公开方向转译为小范围、可解释、可暂停的测试，而非既定全域部署。
- **海淀产业语境：** 以“AI + 5+3 + 科技服务”的关系组织三区两翼，使研究、转化、生活、维护和公共回报在同一条遗产线内互相可见。

# v0.2（75分）→ v1.1 设计评审记录 / Design Critique Record

**设计意图 / Intent**：把已通过仓库准入、得到 75/100 公开评审记录的AI城市设计提交，转为一份人可以从远处读懂总体关系、从近处看见空间机制、并能追问证据边界的城市设计方案。75 分是已发生的评审记录，不被改写为对 v1.1 的预先评分。

## 1. 总体图面 / Overall boards

**观察 / Observation：** v0.2 已有总览、原则、节点与指标，但生态、场景、实施与品牌多由段落承载，审阅者需要跨页拼接。

**原则 / Principle：** 城市设计总图应先提供“线、节点、跨越与停留”的空间层级，文字与指标只在读者需要确认时靠近出现。

**问题 / Question：** 审阅者能否在十秒内识别轨痕主线、三处公地、两翼、区域接口和暂定边界的不同可信度？

## 2. 重点区表达 / Key areas

**观察 / Observation：** v0.2 的三个节点已有不同命名，但“谁在用、在哪里、何时停止、如何交接”仍没有集中呈现。

**原则 / Principle：** 差异化不是换一个颜色，而是让每处空间承担独有的公共关系、剖面、使用者、暂停门和维护动作。

**问题 / Question：** 如果把名称遮住，读者能否从剖面、活动和门槛识别“验证、翻译、回报”三种不同公地？

## 3. 密度与留白 / Density and whitespace

**观察 / Observation：** v0.2 的图册已建立秩序，但图和文字之间尚有“观点多、证据少”的阅读断点。

**原则 / Principle：** 留白是空间关系的一部分；每张图只讲一个主故事，相关信息紧邻，不相关信息拉开距离，使用稳定的8/16/24/32/48/64节奏。

**问题 / Question：** 每个图面是否把40–60%的空白转化为标题、关系和证据之间的呼吸，而不是留作未完成的框？

## 4. AI视觉语言 / AI visual language

**观察 / Observation：** v0.2 的AI治理文本严谨，但还未以一张可读协议让公众看清每项服务的暂停理由。

**原则 / Principle：** AI在城市设计中的视觉角色应是可解释的服务界面，而不是炫目的技术背景。

**问题 / Question：** 每一项AI内容是否同时回答了“谁使用、在哪里、谁解释、如何退出、谁维护”？

## v1.0 的基础与 v1.1 的补强 / v1.0 base + v1.1 refinement

- 新增原创 J·Z COMMONS 标志、色彩、组件和地标-服务关系，使“品牌”成为可维护的公共工具，而不只是命名。
- 用生态接口星图、区域协同接口、十张场景卡协议和实施交接三件套，把生态、场景、治理和落地从散段文字变为可单独审阅的图面。
- A3 由 6 页扩展为 9 页，A0 将总体、节点、品牌、场景和实施置于同一视线；互动页以键盘可用的走读模式提供另一条人类阅读入口。
- 用八个方法案例、北京—海淀校准、明确的“不照搬什么”和“协同接口不等于合作承诺”约束设计借鉴与表达边界。
- v1.1 新增有独立来源、许可和“非空间证据”标记的三联概念氛围图，使三处公地中不同人群、人工服务、维护和无障碍关系可在分析机制之外被直观读到。
