# 研究叙事与成果导读

## 1. 项目思考

京张铁路创新带不是在既有城市设计上附加几项 AI 设施，而是一次面向 AI 时代的规划范式试验。项目有两个嵌套对象：京张的空间、生态、场景和运营是直接对象；AI Agent如何以可复用、可审计、可迭代的方式参与城市规划是根本对象。京张因同时面对百年铁路遗产、中关村创新网络、城市更新、公共利益、资料缺口和快速迭代的智能体技术，成为检验这条路径的现实试验场。

本方案不以“自动完成规划”为目标，而让Agent沿来源准入、底数图谱、识别推演、空间场景、实施运营、监测治理、分众发布和版本回写参与完整规划链。Agent负责生成可追踪候选、反证、影响和复盘草案；人类负责来源准入、公共价值取舍、法定审定、专业安全、空间权利与正式发布。场地成果和方法成果同等重要，评价标准是可追溯性、场地针对性、公共价值、可逆性和持续学习能力，而非文本、图片或自动化数量。

成果明确分为三个相互校验的部分：**总体理解方案**回答AI时代发生了什么变化、京张的独特矛盾和总体取舍是什么；**AI Agent规划操作方案**回答底数、推演、反证、协商、人类门和版本回写怎样组织；**城市规划设计方案**回答在京张什么地方、为谁、解决什么问题、形成怎样的空间与服务、怎样启动和退出。前两部分最终必须服务第三部分，第三部分又必须以真实场地矛盾检验前两部分，不能用方法术语或效果图代替空间决策。

| 成果部分 | 独立回答的问题 | 必须落到的京张对象 | 本版形成的实质成果 |
|---|---|---|---|
| 总体理解方案 | AI时代为什么需要改变规划对象与项目取舍 | 43.6平方公里统筹研究层、11.4平方公里总体设计层、铁路遗产公共脊梁和三重点区的差异 | “铁路公共底盘+创新接力+可逆场景+人工责任”的总体判断，以及众智园可信测试、原点社区公共共创、大钟寺真实需求入口的差异化定位 |
| AI Agent规划操作方案 | 资料不完整、价值冲突和模型不确定时怎样形成可审查判断 | 三层范围九层资料、开发者散步道、大钟寺四象限、六类任务和三区交接 | 证据准入、问题与反证、多情景、空间转译、五道人类规划门、五道成果发布门、两次候选退回和五类规划合同 |
| 城市规划设计方案 | 总体结构、专项关系和重点区服务怎样真正组织 | “一带三区两翼”、铁路遗址公园、众智园、AI原点社区、大钟寺及六个工作点 | 四级空间结果、生态接力、13场景、12类组件、三文化五导览、19项活动、JZ-01—06、G0—G3/X和15项父指标 |

三部分使用同一证据源，但不得互相替代：第一部分不能以“AI时代”口号代替京张判断；第二部分不能以Agent流程代替规划取舍；第三部分不能以精美图像代替正式空间、专业签署和实施责任。

本项目判定“真正规划方案”的最低合同，不是有没有精确坐标，而是每个重点区和工作点能否同时给出：场地依据、目标人群、核心矛盾、空间前后台、物理组件、一天使用流程、普通服务保底、人工责任、启动证据、指标与停止恢复。正式红线、载体、权属、预算、容量或基线缺失时保留`unknown/provisional`，同时作出低后悔的空间关系和实施取舍；不以虚假精度冒充专业深度。

AI进入规划必须同时运行“证据—计算”和“价值—协商”两条回路。Agent可以处理来源、规则、叠合、模拟、政策传导和版本差异，却不能从可见行为自动断言不可见动机，也不能替公众设定价值权重。真实受影响者、社区规划师、专业人员和具名责任主体通过访谈、共同走查、少数意见保留、申诉和人工决定完成价值回路；机器输出的动机只保留为待核假设。[source:LIANG-PLAN-FUTURE-I-20260828] [source:LIANG-PLAN-FUTURE-II-20260829]

全文不是从点位清单出发，而沿“时代变化—传统断点—Agent增强—人类边界—京张验证—结果反证”展开。城市认知、问题定义、逻辑推演、空间转译、公众协商、实施治理和成果表达构成七个切入角度；六个具象点只用于检验框架能否在不同场地矛盾中成立，不代表研究以点位数量或设计细度为中心。

“Agent”统一分为三层：规划生产Agent参与来源、诊断、推演、空间转译与复算；官方六类任务Agent组织品牌、生态、场景、公共空间、文化与运营成果；城市运行Agent是未来进入街区服务和治理的候选系统。前两层是本次研究工作方式，第三层尚未运行；三者不能相互冒充。

京张以场地矛盾而非概念名称验证方法：遗产和公园底盘要求低侵入叠加，AI原点社区要求开放前台和可纠错协作，众智园要求公众界面与受控测试分离，大钟寺要求在空间锚点不完整时由共同走查取代工程路线。开发者散步道和大钟寺四象限两次桌面实验已经记录“候选—缺口—人工门—退级”的过程；它们证明Agent的价值首先是暴露错误确定性，而不是增加方案数量。

从城市规划专业角度，AI时代不是否定用地、交通、生态和法定底线，而是在稳定公共底盘之上增加任务网络、服务接口、时间节律和治理协议四类显性规划对象。一个AI场景必须同时回答空间、任务、接口、时间和治理；任一可变层退出后，公共通行、休憩、无障碍和普通服务仍必须成立。法定与专业底座设定不可突破的边界，战略与城市设计在边界内组织多情景，运营协议只验证获授权的小样，运行数据不能自动代替法定决定。

本方案把《项目研究总纲 V2.0》转译为五个连续动作：建立七类底数与数据图谱；由多 Agent 并行完成问题、目标、对策和反证识别；把工作、生活、学习、公共交往和治理变化转成“稳定公共底盘 + 可逆场景”；用日/周/季/年活动和六段转化链组织长期运营；把同一份判断转成专业报告、公众页面、双语图件和机器可读文件。`verified`、`background`、`design_proposal`、`provisional` 和 `unknown` 不得混写。

## 2. 空间与创新链

三层范围分别承担生态统筹、总体城市更新和重点区域详细设计。工作概念“京张智脉共生带”以京张铁路遗址公园为历史与公共空间主轴，以众智园 AI 自主创新加速区、北京 AI 原点社区和大钟寺 AI 产业集聚区为三类创新区域，以中关村科技服务翼与小月河场景赋能翼承担专业服务、公共场景和知识回流，形成“一带三区两翼”。该结构是待公众测试和授权的研究关系，不替代法定红线、控规、权属或工程线位。

三区采用不同的空间骨架而非同一种“AI展厅”：众智园是“公共验证前台—安全阈值—受控测试后台”，AI原点社区是“公共共享前台—安静共创中场—专业转介后台”，大钟寺是“共同走查—单服务试用—需求复盘—问题回传”。大钟寺确认真实需求，AI原点社区把需求转成问题卡、开源任务或人工转介，众智园完成具备条件项目的受控验证，失败记录和退出条件再回到需求提出者与规划版本；缺少责任人、证据或人工接管的环节不得对外宣称已经形成创新闭环。

生态主链严格采用“R科研—O开源—C算力—D数据—T测试—I孵化—F资本—M市场”八段接力；真实问题是输入，G治理是贯穿横梁，K知识是运行回写，专业/伦理复核是可以否决的闸门而非生产阶段。众智园先验证算力、数据和可信测试接口；AI 原点社区验证研究、开源与孵化交接；大钟寺先做需求、资本服务和市场验证。所有资源、活动、算力、机构和运营主体均需要后续授权或实证，不从片区名称推导既成事实。

为避免总体愿景停留在口号，本方案每个重点区选取两个可小样、可观察、可降级的工作点：

## 4. 数据、运营与成果表达

研究底座目前形成 33 条文化节点、16 条权威文化补充来源、7 个全球案例、24 条案例证据、13 张场景卡、8 类用户与旅程、19 项活动、15 项父指标、15 项专业深度合同、9 层 GeoJSON 以及 20 个 JSON/29 个 CSV 研究文件。指标基线、运行实例和真实运营事件仍为 `unknown`、`null` 或空数组，不能被解释为“没有问题”或“已经运行”。

多模态成果采用同源派生：来源/主张/缺口台账 → 关系图谱 → JSON/CSV/GeoJSON → 证据图和场景卡 → 双语离线 HTML → A3/A0 与 PNG → manifest、哈希、版权和自检。公众可以看到“这是什么、是否已建、我能否拒绝、如何人工咨询”；专业人员可以追溯来源、公式、限制和复算；机器读取稳定 ID 和状态。高风险规划审批、工程安全、医疗、教育、投资、采购和公共荣誉一律转人工或拒答。

## 5. 当前成果边界

本叙事与 `proposal.md`、GeoJSON、指标、矩阵、双语图件、A3/A0 PDF 和离线 HTML 同源。正式包当前为 `ready_for_review`，本地结构、双语、视觉、专业证据和自检链已通过；这不等于组织方正式评分、PR 合并或 100 分。官方正式边界、现场测绘/访谈、专业签署、运行主体和真实试点实例仍是下一阶段外部输入；一旦取得正式几何，必须整体替换 9 层空间数据并重算指标、图件、HTML、PDF、manifest 和全部校验。

## 3. 统一工作协议

1. **接收**：总控 Agent 发出版本化输入包，列明数据时点、空间尺度、许可、缺口和不得推断项。
2. **分解**：子 Agent 将问题拆成事实、假设、目标、方案、指标、风险和反证，不把“应当”当成“已经”。
3. **证据化**：每个主张绑定 `source_id`、`assumption_id`、`metric_id`、`depth_id` 或明确的 `gap_id`；全球案例只支撑机制背景。
4. **空间化**：只使用同一版本 GeoJSON；暂定几何只能做关系推演、NTS 和一致性复算，不能升级为红线或工程线位。
5. **场景化**：每个场景写清使用者、入口、AI 做什么、人工做什么、非数字替代、指标、停止、清理、恢复和申诉。
6. **交接**：输出包含 `input_refs / reasoning / output_refs / unresolved / release_gate`，由总控 Agent 处理冲突；冲突未解决时保留两种解释并降级发布。
7. **发布**：事实门、空间门、权利门、识别门、发布门逐项通过后，才可由 text-only 升级为静态展示、预约试运行或有限开放。

## 4. 统一状态与发布决策

| 状态 | 含义 | 可做 | 不可做 |
|---|---|---|---|
| verified | 直接来源可核对 | 进入正文事实和证据图 | 不能扩大空间/时间粒度 |
| background | 全球案例或政策背景 | 支撑机制比较 | 不能写成海淀统计 |
| design_proposal | 规划建议 | 进入方案、项目和原型 | 不能写成已批准 |
| provisional | 暂定几何或关系 | 研究讨论、NTS、复算 | 不能作为红线、权属或工程依据 |
| unknown | 尚缺证据或运行数据 | 进入缺口、复算触发和人工门 | 不能当作零、达标或已运行 |

总控 Agent 只有三种发布决定：`GO`（证据和权利满足，可按当前状态发布）、`CONDITIONAL GO`（可研究展示，但必须显著披露限制）、`NO-GO`（缺少事实、空间、权利、安全或专业条件，停止对外升级）。本包的正式几何和真实运行均保持 `CONDITIONAL GO` 或 `NO-GO`，不以图面完成度替代外部核验。

## 5. 规划决策五门与成果发布五门

规划生产采用G-Fact、G-Value、G-Spatial、G-Pilot、G-Release，分别控制事实升级、价值取舍、空间准入、试点启动和对外发布。以下五门只用于成果发布与权利审查：

- **G-Fact 事实门**：来源、时点、尺度、异文与反证可回读；
- **G-Spatial 空间门**：边界、拓扑、权属、路权、文保、交通、市政与无障碍不被越权推断；
- **G-Rights 权利门**：版权、商标、字体、肖像、数据、撤回和许可可追溯；
- **G-Brand 识别门**：总名、L0-L5、中英、无障碍、纠错和公众理解一致；
- **G-Release 发布门**：双语、图注、离线、manifest、哈希、状态、人工签署与版本事件齐全。

任一门失败，成果自动降级为 `research_contract`、`text_only` 或 `offline_prototype`，并登记停止、清理、通知、复盘和重启条件。

# 附录 B｜六类 Agent 读者成果卡


本组成果卡把“谁做了什么”落实为问题—证据—推导—空间/场景—指标—人工门—未决项。卡片中的“完成”指研究合同完成，不指专业签章、运营落地或官方评分。

- **问题**：一条铁路遗产与 AI 创新带如何拥有统一、可传播且可撤回的识别系统？

## Agent.2｜全球生态与运营

- **问题**：研究、开源、测试、孵化、资本和市场怎样形成可交接的创新生态，而不是简单复制园区？
- **输入/证据**：七个全球案例的 24 条事实、迁移限制和官方任务；`D2SRC-B2-*`、`A-ACTOR-001`、`A-B5-RUNTIME-001`。
- **推导**：从案例抽取“R科研—O开源—C算力—D数据—T测试—I孵化—F资本—M市场”八段生产主链，以真实问题为输入、G治理为横梁、K知识为回写，专业/伦理复核作为可否决闸门，再映射一带三区两翼的差异职责。

- **空间/指标**：活动账本、`activity_ledger_count`、`monitoring_parent_metric_count`、状态公开率、停止清理率；运营主体和真实机会编号仍 unknown。
- **人工门/未决**：G-Fact、G-Spatial、G-Release；不得写入机构、资金、算力、日期或招商承诺。

## Agent.3｜AI 场景与用户

- **问题**：AI 时代新的工作、学习、生活和交往方式如何进入具体街区，同时不把机器交给高风险决策？
- **输入/证据**：8 类用户/旅程、13 张 B3 场景卡、4 类产业测试、隐私与人工门；`SCN-B3-01`—`SCN-B3-13`、`A-DATA-PRIVACY-001`。
- **推导**：每张卡按问题—需求—目标—数据—空间—AI 做/不做—人工接管—非数字替代—指标—停止/恢复编排，先 text-only，再静态展示、预约试用和有限开放。
- **结论/成果**：形成全栈测试、AI 原点共创、青年第三空间、公共服务驿站、商业测试廊、四象限智行核查等 13 个候选场景；医疗只解释分流、教育只支持共学、商业只做自愿试用。
- **空间/指标**：公共服务连续性、无障碍可达、人工转接率、知情拒绝率、投诉响应和清理闭环；不把用户画像当本地统计。
- **人工门/未决**：G-Fact、G-Spatial、G-Rights；需现场走查、隐私评估、行业责任主体和服务基线。

## Agent.4｜公共空间与 AI 地标

- **问题**：京张铁路遗址公园如何让 AI 创新被看见、被理解、被质疑，而不是增加一组孤立设备？
- **输入/证据**：公共空间、遗产、无障碍、场景和权利缺口；`GREEN-001`、`PUBLIC-001`、`A-HERITAGE-001`、`A-KEY-AREA-ANCHOR-001`。
- **推导**：先稳定公共底盘（通行、遮阴、休息、纸质信息），再叠加可撤组件和人工讲解，最后才讨论有限开放；所有组件有撤回和维护条件。
- **结论/成果**：提出“开发者散步道·开源成果里程廊”、智能体贡献荣誉墙、京张AI时光站三类 AI 地标候选，以及 12 类公共空间组件；均为 NTS/text-only 候选，不绑定暂定坐标。
- **空间/指标**：公共空间比例工作值、无障碍连续性、展示许可完整率、维护响应、撤除时间；不画正式文保线、桥隧或永久地标。
- **人工门/未决**：G-Spatial、G-Rights、G-Release；需公园管理、文保、通行和无障碍专业复核。

## Agent.5｜文化叙事与国际传播

- **问题**：铁路文化、中关村文化和 AI 新文化如何形成可核对、可纠错、可双语传播的共同叙事？

## Agent.6｜实施监测与专业深度

- **问题**：规划如何从概念变成可试、可停、可复算、可学习的实施闭环？

- **结论/成果**：JZ-01—JZ-06 项目台账、日/周/季/年运营闭环、四层停复协议、15 项横向专业接口和逐条合规矩阵；新增逐项实施交接登记和C0—C5公众共定义协议，把载体、运营者、费用、基线、签章与少数意见变成G2前的明确证据槽。
- **空间/指标**：`key_area_count`、`selected_detail_point_count`、`activity_ledger_count`、`monitoring_parent_metric_count`；运行机会、基线、目标、专业签署和实际事件保持 unknown/not_created。
- **人工门/未决**：G-Spatial、G-Fact、G-Release；主体、载体、工程量/询价、专业签章、分群基线和真实受影响者共定义未到位不进入G2；当前值为unknown/not_started，合同完成不等于专业或参与完成。
