# 京张智链｜JING-ZHANG AI RUNTIME

> **The City as an AI Runtime**
>
> 百年前，京张铁路让人、货物与资源进入现代城市；今天，AI Urban Runtime 让智能进入城市，并让城市拥有测试、观察、批准、暂停和回滚 AI 的能力。

## 设计依据与资料清单

本方案遵循仓库 `urban-design-ai-submission` Skill、公开任务书、结构化任务包、主题赛道与投稿模板。当前版本将 provisional 几何仅作为概念设计与 intake 自检依据；不把 provisional polygon 当作官方红线、法定控规或精确面积结论。[source:SITE-PACKAGE]

项目 README 明确将创新带组织为“三个核心区 + 两翼”，并将任务归纳为总体概念、AI 创新生态、AI+场景、京张遗址公共空间、文化叙事与长期运营六类任务。[source:README]

## 一、总体概念：城市作为 AI Runtime

传统智慧城市倾向于“城市 + AI 服务”；本方案改为“城市作为 AI 的运行时环境”。任何 AI 场景都必须经历 Proposal → Simulation → Sandbox → Human Validation → Production → Observability → Feedback 的生命周期。

### 命名与 Logo

项目名称为 **京张智链 / JING-ZHANG AI RUNTIME**。视觉母题采用“轨道 + 节点 + 状态 + 反馈环”，不使用泛化的发光科技城市视觉。Logo 建议由一条代表京张历史轨道的连续线与一个代表 Runtime State 的节点组成；状态变化用节点形态而非颜色承担主要信息。

### 一带总体空间逻辑

以京张铁路遗址及公共空间为 Runtime Spine，形成“一核、一环、三区、两面、多沙盒”：一核为 AI Urban Runtime Core；一环为 Jing-Zhang Runtime Loop；三区为 Sandbox / Staging / Production；两面为 Control Plane 与 Experience Plane；多沙盒为分布式 AI 场景实验节点。[source:AGENT-TASKBOOK]

## 二、全球 AI 创新生态与三区两翼

### Sandbox｜众智园

定位为 AI Experiment Environment：研究、机器人、自动驾驶、开放硬件、AI 基础设施、安全测试与原型开发在这里获得受控空间。核心原则是 **Build / Test / Break**。

### Staging｜北京 AI 原点社区

定位为 Human Validation Environment：研发团队与真实居民、学生、工作者、访客共同验证 AI。核心原则是 **Meet / Experience / Validate**。

### Production｜大钟寺 AI 产业聚集区

定位为 Real-world AI Environment：AI 商业、办公、服务、文旅、零售和城市智能体进入真实运营。核心原则是 **Deploy / Operate / Scale**。

### Control Plane｜中关村科技服务翼

承担政策、标准、知识产权、资本、人才、开源、算力和全球创新网络等支撑功能。

### Experience Plane｜小月河场景赋能翼

承担医疗、教育、交通、商业、文化、公共服务与生活场景的体验和运营反馈。

全球案例研究在正式深化阶段建议围绕深圳、东京、赫尔辛基、伦敦、阿姆斯特丹、旧金山等 AI/创新城市案例进行横向比较，并仅将可验证的空间与运营机制转译为本方案策略；具体案例证据需登记到 `sources.json` 后再进入正式评分材料。

## 三、三层范围工作框架

统筹研究范围对应约 43.6 km² 的创新带叙事；总体设计范围应以仓库发布的官方/可用边界为准；重点区域对应众智园、北京 AI 原点社区、大钟寺三个核心区。当前版本不以 provisional polygon 计算法定面积、容积率或审批指标；正式边界更新后应重新计算全部几何、指标与图件。[source:README]

## 四、总体设计：Urban Continuous Delivery

城市更新从一次性建设转变为持续发布：Observe → Propose → Prototype → Pilot → Measure → Review → Release → Observe。城市空间因此需要可逆、可观察、可人工接管。

### Urban Git

每个 AI 场景拥有版本号，例如 Robot Delivery v0.1 → v0.2 → v0.3 → v1.0。每次升级保留 Change、Evidence、Metrics、Feedback、Decision 五类记录。

### Rollback

AI 场景必须存在 Non-AI Path、Human Override、Exit Condition 与 Rollback Plan。AI 故障时仅关闭 AI overlay，不得让普通城市功能同时失效。人工服务台、传统信息设施、非 AI 配送路径、无障碍备用路径等均作为 AI 城市的容灾基础设施。

## 五、重点区域详细设计

### 1. 众智园｜SANDBOX

形成 AI Test Street、Robot Yard、Model/Agent Lab、Open Hardware 场景。低速机器人、自动驾驶、城市感知等首先在边界明确的实验环境运行。

### 2. 北京 AI 原点社区｜STAGING

形成 Human Test Commons、社区共创空间、AI 学习与开发者空间。AI 第一次面对真实居民，强调可退出、人工复核、可解释反馈与无障碍。

### 3. 大钟寺｜PRODUCTION

形成 AI Commerce、AI Service、AI Office、AI Tourism 与 Civic Agent 等生产级场景。生产环境仍保留人工接管和回滚节点。

## 六、AI 创新生态、人才画像与场景系统

目标用户至少包括：AI 研究者、创业团队、企业员工、青年开发者、周边居民、访客与公共服务使用者。场景以“空间 + 服务 + 数据 + 人工复核 + 运营主体 + 风险边界”定义。

### 旗舰场景

1. **SCN-001 Robot Delivery Street**：G2→G3→G4，低速配送、人工接管与非 AI 配送并存。
2. **SCN-002 Autonomous Mobility Sandbox**：G1→G2，自动驾驶与无人接驳首先进入封闭试验空间。
3. **SCN-003 AI Health Navigator**：G2→G3→G4，提供信息、导航、预约、翻译与无障碍辅助，不替代医生或正式医疗决策。
4. **SCN-004 AI Education Commons**：G2→G3，支持学习、开发、研究与公共教育。
5. **SCN-005 AI Retail District**：G3→G4，支持购物、库存、服务、翻译和导航增强。
6. **SCN-006 AI Civic Agent**：G3→G4，辅助城市信息、公共服务导航、政策解释和社区反馈；最终行政决定必须保留正式人工制度。

正式提交应扩展至不少于 10 张完整场景卡，其中至少 3 张为产业测试验证场景；每张卡映射到空间、用户、数据、隐私、人工复核、运营主体和风险。[depth:scenario_system]

## 七、用地、建筑规模与拆改留

本方案采用“功能角色 + Runtime State”而非虚构法定指标。建筑规模、容积率、高度、拆改留等在缺少正式控规、权属、现状建筑与工程资料时均标记为待确认；概念体量仅作为设计建议，不等于法定控制值。[standard:MOHURD-URBAN-DESIGN-MEASURES]

空间策略优先保留可转化的既有建筑、连续公共空间与可逆实验空间，并通过公共首层、慢行接口和场景节点把产业创新与日常生活连接。

## 八、交通、轨道、市政与公共服务

Runtime Spine 采用“铁路遗产公共空间 + 慢行 + 轨道接驳 + 低速 AI Mobility”的复合结构。AI 交通优先低速、可监管、可人工接管的场景；非 AI 步行、骑行和公共交通路径始终保留。

![交通慢行与蓝绿公共空间复合系统图](assets/figures/mobility-bluegreen.png)

## 九、蓝绿空间、公共空间与城市风貌

京张遗址公园、小月河及相关蓝绿空间作为 Runtime Loop 的公共界面，串联开发者散步道、开源成果展示廊、AI 场景体验节点与社区活动空间。AI 地标采用“贡献可见、技术可理解、公共可参与”的原则。

建议三个核心荣誉/朝圣节点：

- **AI Milestone Wall**：记录 Agent、开发者与开源成果的长期贡献。
- **Open Source Gallery**：展示可复用 AI 城市设计方法与项目版本。
- **Jing-Zhang Runtime Gate**：把铁路历史、AI 版本与城市未来叙事压缩到一个公共入口节点。

以上均为概念建议，不表述为已批准建设。

## 十、实施、运营与活动体系

分三阶段：

**Phase 1｜2026：Build the Runtime**：完成公共空间主轴、Sandbox 原型、数据与运营机制建设。

**Phase 2｜2027-2028：Stage the City**：扩大社区验证、AI 场景开放与开发者活动。

**Phase 3｜2029+：Scale the Network**：将成熟场景连接为跨片区 AI Urban Runtime 网络。

年度活动建议包括 Jing-Zhang AI Runtime Week、Developer Walk、Open City Demo Day、AI Urban Design Review、社区体验日。活动、招商、资金和政策均为概念建议，具体实施需经正式审批与运营主体确认。

## 十一、指标体系、面积复算与合规

本方案建立四类核心指标：

- **AI Reversibility Index**：AI 故障后恢复 baseline city state 的能力。
- **Urban AI Permission Index**：AI 从数字模拟到城市级网络获得的空间权限等级。
- **Human Baseline Availability**：AI 不可用时普通城市功能仍可完成的程度。
- **Runtime Cycle Time**：从提案、测试到发布/回滚的周期。

这些是方案提出的概念指标，不冒充现行法定指标；正式版本应在 `metrics.json` 中给出公式、数据来源、状态与复算方法。

## 十二、风险、版权与数据边界

本方案不使用个人隐私、非公开规划资料或未获授权的数据。所有外部数据必须记录 publisher、URL、retrieval date、license、coverage、transformation 和 limitations。任何 provisional geometry 必须明确标记，并在 official polygon 发布后重新计算。AI 场景不得被描述为已批准政策、工程实施或政府承诺。[source:SOURCE-REGISTRY]

## 十三、下一轮深化

v0.1 的重点是冻结 Runtime 机制与空间结构。下一轮应完成：官方边界核验、三大重点区真实空间落位、10+ 完整场景卡、全球案例证据链、正式指标复算、A0/A3 图面、离线 HTML、双语正文以及完整自检。

> **城市不是 AI 的展示场，而是 AI 的运行时环境。**
