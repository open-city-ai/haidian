Merge Protocol (six-step admission) · Merge Timeslot

Every merge passes six steps — Declare, Verify, Post, Run, Review, Exit; Merge Tokens lock "one segment, one slot" against a public timetable.

governance

① Declare

Merge Application: public purpose, minimal data, responsible party, human alternative, appeal channel, stop threshold, maintenance budget, exit date.

② Verify

Five acceptance checks on evidence, safety, user, operation, public return (Visible / Usable / Debatable / Accountable / Revertable).

③ Post

Signage states purpose, inputs, outputs, risks, owner, status, sunset date.

④ Run

Merge-Token mutual exclusion, public timetable, equivalent non-digital channel with accessible route.

⑤ Review

Objection channels, Public Merge Review, four-type public receipt; human final adjudication, emergency stop, sunset clause.

⑥ Exit

Token return, teardown window, data-deletion evidence, annual Undo drill; failures enter the review archive wall.

Merge Timeslot (time layer)

Six bookable slot types per segment per day: morning care / daytime R&D / evening co-learning / night culture / quiet window / Merge-Day drill. No activity interrupts ordinary passage; equivalent service exists without smart devices. Tributaries keep ≥2 h quiet window daily.

Why a time layer

"When to merge" is designed as rigorously as "where to merge" — the token already carries time (one segment, one slot); the timetable is public and recalculated once official boundaries and regulatory conditions exist.
